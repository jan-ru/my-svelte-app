# Conventions

- **TypeScript only.** Write all source in TypeScript: `.ts` files and Svelte `<script lang="ts">`. Do not add `.js`, `.mjs`, `.cjs` or `.jsx` files. Scripts in `scripts/` are `.ts` too and run with `node scripts/<name>.ts` (Node 24 strips the types). `npm run check:ts-only` enforces this and CI runs it.
- **Type-check and lint before committing:** `npm run check` (svelte-check, strict, with `noUncheckedIndexedAccess`) and `npm run lint` (ESLint with typescript-eslint `strictTypeChecked` and eslint-plugin-svelte, config in `eslint.config.ts`; `max-statements` caps a function at 40 statements, so split a longer one rather than raise the limit). Both must report 0 errors, and CI runs both. Formatting is Prettier's (`.prettierrc`; `npm run format`, CI runs `npm run format:check`); Markdown, `package.json` and generated files are left alone. Read an element the data guarantees with `at()` or `get()` from `src/lib/at.ts` rather than `!`.
- **Style: mostly functional, effects at the edge.** This applies to new and changed code; do not rewrite existing code only to match it.
  - **Data shapes are `readonly`.** Interfaces and types that describe data (rows, views, API results) use `readonly` properties and `readonly T[]`, and constant tables use `as const`. Build a new value instead of changing one in place.
  - **Prefer `map`, `filter`, `flatMap`, `some` and `find` to a loop** where that reads better. A loop is fine when it is clearer, for example when it builds up several results at once or must stop early.
  - **Keep I/O thin.** Network calls, caches, cookies, logging and environment reads stay in small functions at the outside (`fmp.ts`, `yahoo.ts`, `hooks.server.ts`, route files). Parsing, formatting and decisions are pure functions that take data and return data, so tests need no mocks; pass fetchers in as arguments.
- **Effect** (`effect`, pinned exactly) is allowed only in the source modules of `src/lib/server/` (ADR-013): `yahoo.ts`, `yahoo-parse.ts`, `fmp.ts`, `fmp-info.ts`, `eulerpool.ts`, `eulerpool-parse.ts` and `http.ts`, and only once each has moved, which `effect-boundary.test.ts` lists. Their exported functions keep their promise signatures and the existing tests stay the contract. Import by subpath (`effect/Effect`), route everything that can throw through `Effect.try` or `Effect.tryPromise`, keep a test per source that no upstream text reaches `detail`, and write against the installed `.d.ts` (v4, not v3). Not used: retries, layers, the logger, `Config`, `Redacted`, `Cache`, `@effect/vitest`.
- **Imports:** use the `#lib/...` alias for `src/lib` (declared under `imports` in `package.json`). Do not use `$lib` or `config.alias`, which SvelteKit 3 deprecates.
- **Tests:** `npm test` (Vitest, no network). CI runs `npm run test:coverage`, which fails if coverage of `src/lib` drops below the thresholds in `vitest.config.ts`, so add tests with new code. `npm run test:e2e` (Playwright, after `npm run build`) loads every page in Chromium and fails on page errors, CSP blocks or serious axe violations; CI runs it in the `test` job. `npm run check:data` fetches the real NYU files; it also runs monthly in GitHub Actions (`check-data.yml`).
- **Branches:** `main` is protected by a ruleset that requires a pull request and a passing `test` check on a branch that is up to date with `main`, so update the branch and let `test` run again when another PR lands first. Work on a branch and open a PR. Do not merge without the owner's approval.
- **Generated data:** `src/lib/data/*.json` come from `npm run build:crosswalk` and `npm run build:companies` (see `docs/crosswalk.md`). Do not edit them by hand. Each has a hand-written `*.d.json.ts` beside it (`allowArbitraryExtensions` in `tsconfig.json`) that gives the import its type, so importers never cast; `data.test.ts` and `gdp.test.ts` check the real files have that shape.
- **Release overview PDF:** `release-assets.yml` builds it at each tag from `docs/overview.md` (curated parts only), `docs/adr/`, `CHANGELOG.md`, `docs/quality/README.md`, git and the open issues (`scripts/build-overview.ts`, pure code in `src/lib/overview/`, which imports relatively with `.ts` because Node runs the script directly). A new accepted ADR needs a theme in `ADR_THEMES`; an open issue needs a `lane:*` label.
- **Design tokens** for the Horizon theme come from Figma exports in `design/horizon/` through `npm run build:tokens` into `src/lib/styles/generated/`. Do not edit those CSS files (`tokens-data.test.ts` checks they match). A name goes into `ALIASES` in `src/lib/tokens-tables.ts` only if its value equals a Horizon Morning token exactly; names in `ADOPTED` take Horizon's value on purpose and change the look. The layout grid is not in the exports: `GRID` in `tokens-tables.ts` was read by hand from Figma. How it works, the adopted names and the grid helper: `docs/horizon-tokens.md`.
- **`/financials` is behind Sign in with Google (ADR-014).** Never cache it publicly. Never log or return the FMP URL or key, or Yahoo error text to visitors. Keep `$app/env/private` reads in `hooks.server.ts`, `src/routes/financials/` and `src/routes/login/` (the one exception is the four `process.env.ISR_BYPASS_TOKEN` reads in the public routes' `config` exports, which run at build time). Environment variables are declared in `src/env.ts`. Links from API data must pass `safeUrl`. A view never mixes data sources, and a source module never imports another source's module (`source-boundary.test.ts`). Sources, Eulerpool, adding a tab and testing components: `docs/financials.md`.
- **Valuation page** (`/financials/valuation`) sits under `/financials`, so it shares the login, the private caching and the env rule. Peers are picked by hand; an uploaded private-company template is never stored; Eulerpool's fair value and quality score never enter the calculation. Details: `docs/financials.md`.
- **Login** is Sign in with Google (ADR-014): `/login` (private, `no-store`) offers it and the `logout` action; `/login/google` starts it and `/login/google/callback` finishes it. Only Google-verified addresses on `ALLOWED_EMAILS` (exact, comma-separated, never committed) get a session, and hooks re-check the list on every request. Previews have no login (Google needs each callback URL registered). Logs carry an 8-character keyed hash of the address (`userHash`), never the address. Every "Log in" link goes to `/login` through `loginHref(from)` and logout posts to `logoutAction(from)` (`src/lib/return-path.ts`); `from` is an allow-listed path (`RETURN_PATHS`) with its query kept. A new page that offers a login adds its path to `RETURN_PATHS`. The login code uses Web Crypto, not `node:crypto`, so it runs on Vercel, Cloudflare and a VPS.
- **Page access** (ADR-015): `ADMIN_EMAILS` (each also on `ALLOWED_EMAILS`) get every page and `/settings`; everyone else gets the pages `PAGE_ACCESS` grants, and nothing when it is unset. Hooks check it on every request against the matched route (`event.route.id`), never the raw URL, so `locals.authed` means "signed in and may use this page"; `locals.denied` and `locals.admin` say why. Any route not in `ACCESS_PAGES` or `OPEN_PATHS` (`src/lib/server/page-access.ts`) is closed to signed-in people, so a new route goes into one of them; `page-access.test.ts` fails until it does. `/settings` stores nothing: it writes a `PAGE_ACCESS` value for the admin to paste into the host. It is a 404 for anyone else, never cached, and reads the rules from `locals.settings`, not from `$app/env/private`. The Settings link is shown only on interactive (never cached) requests.
- **Secrets** are Vercel environment variables (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `ALLOWED_EMAILS`, `ADMIN_EMAILS`, `PAGE_ACCESS`, `SESSION_SECRET`, `FMP_API_KEY`, `EULERPOOL_API_KEY`, `ISR_BYPASS_TOKEN`); never commit them. The `test` check runs gitleaks over each pull request's commits (`docs/workflows.md`). A false positive goes into `.gitleaks.toml` with a `description` saying why it is not a secret; never allowlist a real value, and never print one (`--redact`).
- **`ISR_BYPASS_TOKEN` is also Vercel's revalidation secret.** Build and runtime must see the same value, rotating it needs a redeploy, and it should be rotated together with `SESSION_SECRET` (logout does not revoke the cookie value). A request with `x-prerender-revalidate` always gets the anonymous view (`isRevalidation` in `hooks.server.ts`), and without a usable token hooks send `Cache-Control: private, no-store`.
- **Public pages are ISR-cached** for anonymous visitors; their loaders must read the query only through `pageParams(locals.interactive, url, publicKeys)` so that what is cached never depends on the first requester. Anonymous requests see only the `publicKeys` a page names, whose values are part of the cache key; name one only when every value of it is a view anyone may get (today only the size pages' `band`).
- **Size pages** (`/countries`, `/industries`) read `measure`, `country`, `industry`, `sector`, and `band` (which band of the ranking the treemap shows, `src/lib/size/bands.ts`; public, in `PUBLIC_SIZE_PARAMS`); any new query parameter on a public page must be added to `ISR_ALLOW_QUERY` or Vercel drops it for logged-in users too (`SIZE_PARAMS` has a test).
- `src/lib/data/gdp.json` and `src/lib/data/macro.json` (inflation and real growth, see `docs/size.md`) are generated by `npm run build:gdp`; never edit them by hand.
- **Node LTS only.** Stay on the Node LTS line pinned in `package.json` `engines` (now 24), `.nvmrc`, the CI workflows and `@types/node`. Never install or build with a non-LTS Node, and never accept a Dependabot major bump of `@types/node`; changing the line is one deliberate pull request that moves all four together (`src/lib/node-pin.test.ts` fails if they drift).
- **API docs:** `npm run docs` builds a TypeDoc reference of `src/lib` into `docs/api` (git-ignored; config in `typedoc.json`). Warnings fail the build, so an exported signature that mentions an unexported type needs the type exported or listed under `intentionallyNotExported`. TypeDoc reads `.ts` only, so Svelte components are not covered, and it supports TypeScript up to 6.0.x.
- **Svelte MCP** (Claude Code, OpenCode and Pi; setup in `docs/svelte-mcp.md`). When you are unsure how Svelte 5 or SvelteKit 3 behaves, call `list-sections`, then `get-documentation` for the sections whose `use_cases` fit. Run `svelte-autofixer` on every Svelte component you write and repeat until it reports nothing; it does not replace `npm run check` and `npm run lint`. Use `playground-link` only when the user asks, and never for code written to files in this repo.
