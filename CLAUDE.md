# Conventions

- **TypeScript only.** Write all source in TypeScript: `.ts` files and Svelte `<script lang="ts">`. Do not add `.js`, `.mjs`, `.cjs` or `.jsx` files. Scripts in `scripts/` are `.ts` too and run with `node scripts/<name>.ts` (Node 24 strips the types). `npm run check:ts-only` enforces this and CI runs it.
- **Type-check and lint before committing:** `npm run check` (svelte-check, strict, with `noUncheckedIndexedAccess`) and `npm run lint` (ESLint with typescript-eslint `strictTypeChecked` and eslint-plugin-svelte, config in `eslint.config.ts`). Both must report 0 errors, and CI runs both. Read an element the data guarantees with `at()` or `get()` from `src/lib/at.ts` rather than `!`.
- **Style: mostly functional, effects at the edge.** This applies to new and changed code; do not rewrite existing code only to match it.
  - **Data shapes are `readonly`.** Interfaces and types that describe data (rows, views, API results) use `readonly` properties and `readonly T[]`, and constant tables use `as const`. Build a new value instead of changing one in place.
  - **Prefer `map`, `filter`, `flatMap`, `some` and `find` to a loop** where that reads better. A loop is fine when it is clearer, for example when it builds up several results at once or must stop early.
  - **Keep I/O thin.** Network calls, caches, cookies, logging and environment reads stay in small functions at the outside (`fmp.ts`, `yahoo.ts`, `hooks.server.ts`, route files). Parsing, formatting and decisions are pure functions that take data and return data, so tests need no mocks; pass fetchers in as arguments.
- **Imports:** use the `#lib/...` alias for `src/lib` (declared under `imports` in `package.json`). Do not use `$lib` or `config.alias`, which SvelteKit 3 deprecates.
- **Tests:** `npm test` (Vitest, no network). CI runs `npm run test:coverage`, which fails if coverage of `src/lib` drops below the thresholds in `vitest.config.ts`, so add tests with new code. `npm run check:data` fetches the real NYU files; it also runs monthly in GitHub Actions (`check-data.yml`).
- **Branches:** `main` is protected by a ruleset that requires a pull request and a passing `test` check. Work on a branch and open a PR. Do not merge without the owner's approval.
- **Generated data:** `src/lib/data/*.json` come from `npm run build:crosswalk` and `npm run build:companies` (see `docs/crosswalk.md`). Do not edit them by hand. Each has a hand-written `*.d.json.ts` beside it (`allowArbitraryExtensions` in `tsconfig.json`) that gives the import its type, so importers never cast; `data.test.ts` and `gdp.test.ts` check the real files have that shape.
- **`/financials` is password protected.** Never cache it publicly, never log or return the FMP URL or key, and keep `$app/env/private` reads in `hooks.server.ts` and `src/routes/financials/`. The one exception is the four `process.env.ISR_BYPASS_TOKEN` reads in the public routes' `config` exports, which run at build time. Environment variables are declared in `src/env.ts`; `$env/dynamic/private` is deprecated and sees nothing without that declaration. Page state (`tab`, `statement`, `period`) is parsed by `src/lib/financials-nav.ts`; only the selected statement is fetched. Profile, news and prices go through the shared `fmpGet` in `src/lib/server/fmp.ts`; links from API data must pass `safeUrl`. A view never mixes data sources: `src/lib/source.ts` decides the source per ticker (a dot suffix means Yahoo only) and whether a period exists for it (`FMP_SUPPORTS_TTM`). Yahoo goes through `src/lib/server/yahoo.ts` (injectable client) and `yahoo-parse.ts`; never log Yahoo error text to visitors. The shapes both sources produce (`Statement`, `Profile`, `NewsItem`, `PricePoint`) live in `src/lib/source-data.ts` and failures are a `SourceError` (`src/lib/server/source-error.ts`); a source module imports those and never another source's module (`source-boundary.test.ts` enforces it). A new tab is one entry in `TABS` plus one loader in `TAB_LOADERS` (`src/lib/server/financials.ts`) and, if it needs new markup, a component in `src/lib/components/` that `+page.svelte` renders. Components get a render test: Vitest compiles `.svelte` files through the plugin in `vitest.config.ts` and `svelte/server`'s `render` turns a component into HTML (see `financials-views.test.ts`); there is no DOM library.
- **Valuation page** (`/financials/valuation`) sits under `/financials` so it shares the login, the private caching and the env rule above. Its state is the URL (`valuation-nav.ts`), the maths is pure (`valuation.ts`, `valuation-figures.ts`) and loading is in `src/lib/server/valuation.ts`, which reuses the `/financials` fetchers and the Damodaran `getComparison`. Peers are picked by hand; FMP's list is only a suggestion. A private company comes from an uploaded Excel template (`valuation-template.ts`, read in `server/valuation-template.ts`); the file is never stored and its figures travel in the URL as `co` (`valuation-company.ts`).
- **Secrets** are Vercel environment variables (`FMP_API_KEY`, `SITE_PASSWORD`, `SESSION_SECRET`, `ISR_BYPASS_TOKEN`); never commit them.
- **`ISR_BYPASS_TOKEN` is also Vercel's revalidation secret.** Build and runtime must see the same value, rotating it needs a redeploy, and it should be rotated together with a password change (logout does not revoke the cookie value). A request with `x-prerender-revalidate` always gets the anonymous view (`isRevalidation` in `hooks.server.ts`), and without a usable token hooks send `Cache-Control: private, no-store`.
- **Public pages are ISR-cached** for anonymous visitors; their loaders must read the query only through `pageParams(locals.interactive, url)` so that what is cached never depends on the first requester.
- **Size pages** (`/countries`, `/industries`) read `measure`, `country`, `industry`, `sector`; any new query parameter on a public page must be added to `ISR_ALLOW_QUERY` or Vercel drops it for logged-in users too (`SIZE_PARAMS` has a test).
- `src/lib/data/gdp.json` is generated by `npm run build:gdp`; never edit it by hand.
- **Node LTS only.** Stay on the Node LTS line pinned in `package.json` `engines` (now 24), `.nvmrc`, the CI workflows and `@types/node`. Never install or build with a non-LTS Node, and never accept a Dependabot major bump of `@types/node`; changing the line is one deliberate pull request that moves all four together (`src/lib/node-pin.test.ts` fails if they drift).
- **API docs:** `npm run docs` builds a TypeDoc reference of `src/lib` into `docs/api` (git-ignored; config in `typedoc.json`). Warnings fail the build, so an exported signature that mentions an unexported type needs the type exported or listed under `intentionallyNotExported`. TypeDoc reads `.ts` only, so Svelte components are not covered, and it supports TypeScript up to 6.0.x.
